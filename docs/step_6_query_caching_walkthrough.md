# Walkthrough — Step 6: Query Caching

We have implemented a query caching layer that intercepts common questions before they trigger the external Indian Kanoon API and the LLM generation step. This achieves two critical goals:
1. **Cost Reduction**: Prevents repeated ₹0.50–0.90 charges for identical legal queries.
2. **Speed**: Reduces response latency for common queries from ~5-10 seconds to under 50 milliseconds.

---

## What Was Implemented

### 1. SQLite Database Caching ([src/db.py](file:///Users/piyushdokania/legal/src/db.py))
- Added `query_cache` table to the SQLite schema (`legal.db`).
- Fields: `search_query` (Primary Key), `context_text`, `citations`, `llm_answer`, and `created_at`.
- Added helper functions:
  - `get_cached_query(search_query)`: Retrieves the cached response.
  - `cache_query(...)`: Inserts or updates the cache using `INSERT OR REPLACE INTO`.

### 2. Semantic Cache Keys via LLM Query Rewriting
- The cache key is **not** the raw user question, because users ask the same thing in a hundred different ways (*"landlord won't give back my money"* vs *"how to get security deposit back"*).
- Instead, the cache key is the **rewritten search query** (e.g., `"security deposit" ANDD tenancy ANDD refund doctypes: laws`), generated by the very fast and cheap routing LLM in `src/retrieval/rewrite.py`.
- This creates an effective semantic cache.

### 3. Pipeline Refactoring ([src/pipeline.py](file:///Users/piyushdokania/legal/src/pipeline.py))
- Extracted `rewrite_query` to run *before* context retrieval.
- Modified `answer_question` to perform a cache check on `NEW_QUERY` intents.
- **Cache Hit Logic**: If the search query exists in the database, immediately return the cached LLM answer, rehydrate the JSON `citations`, and update the session context. The IKanoon Search, Document fetch, and primary LLM generation are completely bypassed.
- **Cache Miss Logic**: If not found, call `build_context()` and `explain_with_llm()` normally, then save the results into `query_cache`.
- Follow-ups intentionally do not cache their answers, as follow-up answers are highly dependent on the unique context of the conversation.

### 4. Retrieval Context Simplification ([src/retrieval/context.py](file:///Users/piyushdokania/legal/src/retrieval/context.py))
- Simplified `build_context()` signature to take `search_query` directly instead of taking `question` and doing the rewriting internally. This clean separation of concerns made caching possible.
